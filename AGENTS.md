# skinbase — заметки для следующей сессии

## Хранилище файлов капов

Загрузка идёт в **CatBox, при его отказе — в резервный S3-совместимый бакет**.
Причина: CatBox отвечает «успехом» и при этом не кладёт файл (ссылка ведёт на
404 или на пустое тело). Ответ API не считается успехом — оба бэкенда проверяют
результат чтением до записи строки в D1.

- CatBox при наличии резерва делает **одну** попытку, без резерва — три
  (`CATBOX_UPLOAD_ATTEMPTS`). Ждать отказа трижды ради гарантированного успеха
  по второму пути — задержка пользователя.
- `uploadCape()` возвращает `{ value, storage }` — куда легло по факту.
  Поле `storage` решает, добавлять ли файл в альбом: альбом есть только у
  CatBox, и при сработавшем резерве запроса быть не должно.
- Старая библиотека не переносится: адрес файла лежит в колонке `value` у
  каждой строки, поэтому старые catbox-ссылки отдаются как есть.
- Ошибки загрузки отдаются статусом **503**, а не 502: Cloudflare подменяет
  тело 502 своим текстом `error code: 502`, и фронтенд вместо JSON получает
  текст, который не разбирает.

## S3-клиент (`functions/_lib/s3.js`)

Свой клиент AWS SigV4 на WebCrypto, без SDK. Проверен против официального
вектора `aws-sig-v4-test-suite` (`get-vanilla`) — подпись совпадает побайтово.

- Эндпоинт S3 у Supabase: `https://<ref>.storage.supabase.co/storage/v1/s3`
- Публичная ссылка для чтения: `https://<ref>.supabase.co/storage/v1/object/public/<bucket>/<key>`
- **S3-протокол надо включить вручную** в настройках Supabase Storage, иначе
  ключи не создаются.
- `CreateBucket` поддерживается, но **ACL нет** (`x-amz-acl` игнорируется):
  публичность бакета ставится только через REST API или в дашборде.
- Supabase: **версионирование не поддерживается**, `Content-MD5` не поддерживается.
- `S3_REGION` обязателен: без него `s3Configured()` возвращает false и всё
  уходит в CatBox. Это сделано намеренно — переезд переключается настройкой,
  а не правкой кода.

### Переменные окружения

Несекретные лежат в `wrangler.jsonc → vars`: `S3_ENDPOINT`, `S3_BUCKET`,
`S3_PUBLIC_BASE`.

Секреты ставятся так:

```
npx wrangler pages secret put S3_ACCESS_KEY_ID     --project-name skinbase
npx wrangler pages secret put S3_SECRET_ACCESS_KEY --project-name skinbase
npx wrangler pages secret put S3_REGION            --project-name skinbase
```

## Известные грабли

- **`node --check` молчит на ESM-файлах с импортами.** Проверять загрузку
  модуля импортом, а не синтаксис-флагом.
- Тесты подменяют `globalThis.fetch`. Фоновые задачи из `waitUntil` надо
  **дожидаться** (`Promise.allSettled`), иначе заглушка не успевает записать
  запрос и тест проходит, хотя обход происходит.
- Заглушка D1 должна уметь и `run()`, и `first()` после `bind()`: `auth.js`
  зовёт оба. Заглушка только с `run()` даёт 500 из ниоткуда.
- Cloudflare KV `SKINS_KV` остаётся только для legacy-строк вида `kv:<name>`.
